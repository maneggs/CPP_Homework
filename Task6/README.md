### 3. `temperature.cpp`
*Примечание: объяснение появления микроскопического «хвоста» погрешности при обратном пересчёте в `double` оставлено в комментариях внутри `temperature.cpp`.*

**Тестовые данные:** `36.6` °C и `97.88` °F

**Результат работы программы:**
```text
Цельсий: 36.6
Фаренгейт: 97.88
Фаренгейт: 97.88
Цельсий: 36.6
Испорченная прямая формула: 68.6
```

#### 🔍 Сравнение и объяснение работы прямой формулы (до и после порчи масштаба)
* **До порчи масштаба (`36.6 * 9.0 / 5.0 + 32`):**  
  Вывод: **`97.88`**  
  *Объяснение:* Поскольку числа `9.0` и `5.0` записаны с плавающей точкой, компилятор выполняет дробное деление. Коэффициент масштаба вычисляется точно (`9.0 / 5.0 = 1.8`), что даёт правильный результат: `36.6 * 1.8 + 32 = 97.88`.

* **После порчи масштаба (`int scale = 9 / 5; 36.6 * scale + 32`):**  
  Вывод: **`68.6`**  
  *Объяснение:* Оба числа в выражении `9 / 5` имеют целочисленный тип (`int`). По правилам C++ при делении целого числа на целое дробная часть (`.8`) просто отбрасывается (происходит усечение, а не округление). В переменную `scale` записывается значение `1` вместо `1.8`. В итоге формула превращается в `36.6 * 1 + 32`, что даёт неверный результат `68.6`.
